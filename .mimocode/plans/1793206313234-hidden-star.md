# Rencana: Low memory mode untuk Windows + cover musik tetap tampil di software renderer

## Konteks & keputusan user

Proyek: **Olyzano Notch** (Qt 6.8 / C++17 / QML, Linux + Windows).

- Windows idle saat ini: **~190 MB working set / 230 MB private**, "mayoritas graphics driver + 3–4 QML window" (`docs/windows-developer-notes.md:13`).
- Linux sudah punya **Low memory mode** (`MemoryTuner`, software renderer): 133 → ~87 MB PSS, "roughly 50 MB less" (`README.md:575-577`).
- `MemoryTuner` saat ini **Linux-only**: `available()` → false di Windows (`src/platform/MemoryTuner.cpp:38-45`), sehingga kartu **Performance disembunyikan di Windows** (`src/qml/SettingsPage.qml:433`).

Keputusan user:
1. Target utama = **hemat ~50 MB seperti Linux** (190 → ~140 MB working set). User lalu menanyakan **< 100 MB apakah mungkin** — jawaban jujurnya: **mungkin, tapi tidak bisa dijanjikan dari mode software saja**. Buktinya: (a) di Linux dengan software renderer pun masih **87 MB PSS** dan PSS menghitung halaman bersama terbagi, sedangkan Windows WS menghitung penuh halaman DLL yang resident; (b) dokumen menyebut sisa terbesar = "graphics driver **dan 3–4 QML window per layar**" — driver hilang dengan software mode, jumlah jendela tidak; (c) hello-world Qt Quick di Windows saja sudah ~40–60 MB WS. Sasaran dibuat **bertingkat dengan gerbang pengukuran** (lihat "Target bertingkat" di bawah) — tidak menjanjikan angka yang belum diukur.
2. Cover album **wajib tetap tampil** saat renderer software aktif (preventif — bukan bug yang sudah terlihat).
3. Cakupan: **Windows + perbaikan Linux** (fallback cover diverifikasi lokal di Linux).

## Target bertingkat (dengan gerbang pengukur)

| Tier | Target | Cara | Status |
|---|---|---|---|
| 0 | ~190 MB WS (baseline) | — | terukur (`docs/windows-developer-notes.md:13`) |
| 1 | **hemat ~50 MB → ~140 MB** | Low memory mode (software renderer) + trim Windows | dikerjakan sekarang; **diukur dulu** dengan `memcheck.ps1` |
| 2 | **< 100 MB** (permintaan user — diperjuangkan, tidak dijanjikan) | Hanya jika Tier 1 belum tembus, levers berikut diurutkan termurah dulu (lihat "Tier 2 levers") | setelah angka Tier 1 diketahui |

Kalau setelah Tier 2 angka nyata belum < 100 MB, rencana **melaporkan angka apa adanya** sebagai batas realistis — bukan menyembunyikannya dengan trik metrik.

### Tier 2 levers (urut termurah; dikerjakan hanya jika perlu)

1. **Trim working set lebih agresif saat idle** di Windows: selain `trimTimer` 15 dtk (`Main.qml:899`), panggil `memtune.trim()` saat kapsul kembali idle. Ini menurunkan angka *working set* saat diam (halaman jadi standby, kembali di-fault saat disentuh) — jujur: mengurangi metrik WS lebih besar daripada mengurangi footprint; tetap sah karena halaman benar-benar available untuk proses lain.
2. **Perkecil texture saat mode software**: `sourceSize` cover 200→128 dan backdrop 160→96 hanya saat `memtune.running` (software tak butuh oversample) — mengurangi private memory sungguhan.
3. **`QSG_RHI_BACKEND=software`** sebagai belt-and-braces + verifikasi driver GPU benar-benar tak termuat (Task Manager / `listdlls`) — kalau driver masih termuat, di situlah sisa puluhan MB.
4. **Jendela QML per layar** (docs: 3–4 windows/screen) — konsolidasi jendela adalah refactor arsitektural besar; **daftarkan sebagai tindak lanjut terpisah**, jangan dijanjikan di perubahan ini.
5. Marginal: jumlah thread (pool sudah 4), audit image cache — hanya jika sudah sangat dekat dengan 100.

Masalah inti cover: `CoverArt.qml:39` dan `MediaCard.qml:127,234` memakai **MultiEffect (shader)** — `Image` sumbernya `visible: false` dan hanya dirender *lewat* MultiEffect. Proyek sendiri sudah tahu batas ini: `CameraView.qml:25` *"the software renderer cannot draw the live filter"* (pola `layer.enabled: !root.software`). Di software backend, cover musik akan **hilang** tanpa fallback.

## Perubahan per file

### 1. `src/platform/MemoryTuner.cpp` (+ komentar di `MemoryTuner.h`)

| Fungsi | Perubahan |
|---|---|
| `applyEarly()` (:23-36) | Restruktur: blok `#ifdef Q_OS_LINUX` tetap untuk `mallopt`/`MESA_GLTHREAD`. Pembacaan `lowMemory` dari `perf.conf` + `qputenv("QT_QUICK_BACKEND", "software")` (guard `!qEnvironmentVariableIsSet("QT_QUICK_BACKEND")`) jadi **di luar platform ifdef** (berlaku Linux + Windows). Var Wayland `QT_WAYLAND_CLIENT_BUFFER_INTEGRATION=shm` tetap Linux-only. |
| `available()` (:38-45) | `true` untuk `Q_OS_LINUX` **dan** `Q_OS_WIN` (`#if defined(...)`), selain itu false. Ini otomatis menampilkan kartu Performance di Windows. |
| `trim()` (:62-67) | Linux: `malloc_trim(0)` tetap. **Windows**: `#include <windows.h>`, panggil `SetProcessWorkingSetSize(GetCurrentProcess(), (SIZE_T)-1, (SIZE_T)-1)` — padamkan working set (analog `malloc_trim`; halaman kembali saat dibutuhkan). Sudah aktif otomatis lewat `trimTimer` di `src/qml/Main.qml:899` (15 dtk setelah panel ditutup). |
| `restart()` (:69-74) | Linux: `/bin/sh` tetap. **Windows**: `QProcess::startDetached("cmd.exe", {"/c", QString("timeout /t 1 /nobreak >nul & start \"\" \"%1\"").arg(appPath)})` lalu `quit()`. Jeda 1 dtk wajib: proses baru harus menunggu `QLockFile` (`main.cpp:214-218`) dilepas oleh proses lama (quit → teardown → unlock); jalur Linux lama pakai `sleep 1` dengan alasan sama. `timeout` ada di semua Windows ≥ Vista. |
| Komentar header (:5-8, :12, :19) | Perbarui: "Linux and Windows". |

Tidak ada perubahan CMake (sumber sudah masuk build; kernel32 default di MSVC).
Env var Windows cukup `QT_QUICK_BACKEND=software` saja — di Qt 6.8 itu sudah memaksa scene-graph software (tanpa D3D/GL driver); `QSG_RHI_BACKEND` hanya memilih antar RHI backend dan tidak dipakai saat backend software. Jangan set `QT_OPENGL=software`.

### 2. `src/qml/CoverArt.qml` — fallback cover kapsul & toast
Dipakai di `Main.qml:1428` (toast lagu baru) dan `Main.qml:1682` (baris musik kapsul idle).

- Root: tambah `readonly property bool mask: !memtune.running` (pola persis `CameraView.qml:25`).
- `Image img` (:23-31): tambah `anchors.fill: parent`; `visible: c.ready && !c.mask` (di software: cover tampil **langsung**, crop persegi via `fillMode: PreserveAspectCrop` — sudut membulat hilang, gambar tetap muncul). Aman untuk jalur GPU: selama ini pun `visible: false` dan hanya jadi sumber texture effect.
- Root `Item`: `clip: true` agar gambar tidak luber.
- `MultiEffect` (:39-47): `visible: c.ready && c.mask` (GPU saja).
- Rectangle latar (:11-15) + ikon not musik (:16-22): tidak diubah.

### 3. `src/qml/MediaCard.qml` — fallback backdrop blur + cover kartu

Root: tambah `readonly property bool sw: memtune.running`.

**Backdrop blur (:111-137):**
- `anchors.margins: card.sw ? 0 : -70` (−70 hanya untuk blur; gambar polos harus pas dengan kartu).
- `bgArt` (:117-126): `visible: card.hasArt && card.sw`, `opacity: ~0.7` (pengganti kasar brightness −0.32).
- `MultiEffect` blur (:127-136): `visible: card.hasArt && !card.sw`.
- Overlay gradien keterbacaan teks (:138-145): TETAP — `Rectangle`+`Gradient` jalan di software.

**Cover di `face` (:217-251):**
- Tambah `Image` baru sebagai saudara `coverMask` di dalam `face`: `anchors.fill: parent`, `visible: card.hasArt && card.sw`, `source: media.artUrl`, `cache: false`, `sourceSize: Qt.size(200,200)`, `fillMode: PreserveAspectCrop`, `asynchronous: true`. (Image `art` yang ada tidak bisa dipakai langsung: ia di root kartu, tidak bisa anchor ke `face` — QML hanya mengizinkan anchor ke parent/saudara.)
- `MultiEffect` mask (:234-242): `visible: card.hasArt && !card.sw`.
- `art` (:97-105) tetap `visible: false` (sumber effect GPU). `coverMask`, ikon fallback (!hasArt), gradien bayangan: tidak diubah.

**Jalan aman di jalur musik software** (sudah diverifikasi): `ArtColor.qml` (Canvas), Equalizer (Shapes/rect), `MarqueeText` (transform). Di luar cakupan (catatan saja): `Main.qml:1419` (`layer.effect: MultiEffect` tint ikon perangkat di toast), `FileItemDelegate.qml:126`.

### 4. `scripts/memcheck.ps1` — pengukuran Windows (baru)
Model dari `scripts/memcheck.sh`: untuk tiap variant (`default`, `low`):
- Jalankan `notch.exe` (varian `low` dengan `$env:QT_QUICK_BACKEND="software"` yang diwariskan ke child), sampling tiap 10/25/40 dtk: `WorkingSet64`, `PrivateMemorySize64`, jumlah thread via `Get-Process`; cetak MB + selisih; akhiri proses uji.
- Keterbatasan didokumentasikan di header skrip: profil buangan tidak bisa pakai `LOCALAPPDATA` env (`docs/windows-developer-notes.md:17`); **Notch yang sedang berjalan harus ditutup dulu** (single-instance; instance uji akan langsung keluar — skrip memberi peringatan seperti `memcheck.sh`).
- Target pengukuran: `default` ~190 MB → `low` **~140 MB** WS (Tier 1). Skrip yang sama dipakai ulang untuk menilai Tier 2 (target < 100 MB) — setiap lever Tier 2 diukur sebelum dan sesudahnya.

## Urutan implementasi

1. `MemoryTuner.h/.cpp` (Windows: applyEarly, available, trim, restart).
2. `CoverArt.qml` + `MediaCard.qml` fallback `memtune.running`.
3. Build Linux (`cmake --build build`) — qmlcachegen menangkap kesalahan QML saat build juga.
4. `scripts/memcheck.ps1`.
5. User mengukur Tier 1 di Windows → **gerbang**: jika belum < 100 MB dan user ingin mengejar, kerjakan Tier 2 levers (ukur per lever); jika sudah mentok, laporkan batas realistis.
6. Docs (setelah angka terukur; angka placeholder dilarang — tulis hanya hasil ukur nyata).

## Verifikasi

**Linux (lokal, Qt6 + ninja tersedia):**
- [ ] Build biasa lalu `QT_QUICK_BACKEND=software ./build/notch` — mode jalan (`memtune.running` true).
- [ ] Cover tampil di software mode: jalankan player MPRIS (atau fake MPRIS singkat via `python3-dbus` di session D-Bus, artUrl menunjuk gambar lokal), lalu cek kapsul idle (`--shot`/`--shot-page`) — cover terlihat (sudut kotak OK). Jika tidak ada sesi GUI/D-Bus di mesin ini, serahkan cek visual ini ke user dan pastikan binding QML-nya benar lewat review.
- [ ] Mode GPU (tanpa env): visual cover **tidak berubah** (MultiEffect tetap dipakai).
- [ ] `scripts/memcheck.sh build/notch default low` masih ~133 / ~87 MB PSS.
- [ ] `ctest --test-dir build --output-on-failure` (tst_core) lulus.

**Windows (user/CI):**
- [ ] **Gerbang Tier 1**: kartu **Performance** muncul di Settings; toggle + **Restart now** me-relaunch setelah ~1 dtk (lock dilepas); `scripts/memcheck.ps1` → default ~190 MB vs low ~140 MB WS (hemat ~50 MB).
- [ ] Cover musik tampil di mode low (kapsul, toast, kartu Media diperluas).
- [ ] Jendela alpha/transparan tetap ter-composit DWM; animasi pakai CPU lebih banyak (tradeoff yang sudah didokumentasikan di Linux).
- [ ] **Gerbang Tier 2 (jika user ingin < 100 MB dan Tier 1 belum tembus)**: ukur tiap lever (trim idle → sourceSize software → cek driver GPU tak termuat) satu per satu dengan skrip yang sama; catat kontribusi masing-masing. Jika semua lever sudah habis dan angka belum < 100: **laporkan batas realistisnya** ke user dengan rincian komposisi (driver / jendela / baseline Qt) — keputusan soal konsolidasi jendela diambil user sebagai tindak lanjut.

## Risiko

| Risiko | Mitigasi |
|---|---|
| **Tier 1 tidak hemat ~50 MB persis, atau Tier 2 (<100 MB) tidak tercapai** | Rencana bertingkat + gerbang pengukuran: lever diukur satu per satu; jika sudah habis, laporkan angka nyata apa adanya (bukan janji) — kandidat penyebab tersisa: driver GPU yang masih termuat, 3–4 jendela QML/layar, baseline Qt sendiri |
| MultiEffect di software: tidak menggambar (dipastikan) atau berperilaku tak terduga | Sembunyikan via `visible` + tampilkan Image langsung; preseden `CameraView.qml:25,59` sudah dipakai produksi |
| CPU lebih tinggi saat panel bergerak di software | Tradeoff yang sudah diterima & didokumentasikan (Linux) |
| Race restart Windows (lock 100 ms) | Delay 1 dtk eksternal via `cmd timeout`, sama seperti jalur Linux |
| `cmd /c` quoting path | Path berasal dari `applicationFilePath()` (milik aplikasi, tanpa tanda kutip); dikutip di string perintah |
| Trim agresif membuat UI terasa "patah" saat dibuka kembali (fault-in halaman) | Trim hanya saat idle (setelah panel tutup / kapsul idle), tidak saat animasi |
