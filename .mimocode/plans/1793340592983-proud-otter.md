# Plan: Windows search bar — lengkapkan app list + multi-token content filtering

## Goal

Di Windows, search notch (Shift+Space) sering terasa **kurang lengkap** karena catalog hanya Start Menu `.lnk → .exe` (app Store/UWP hilang) dan search hanya match **nama** (keywords kosong). Tambah:

1. **App list lebih lengkap** — Start Menu + UWP/Store (`shell:AppsFolder`)
2. **Content-based filtering** — multi-token query + keywords (folder Start Menu, deskripsi .lnk, path)

User memilih: *Start Menu + UWP/Store* dan *Multi-token + keywords*.

## Design

### 1. Keywords enrichment (classic Start Menu apps)

Di `AppDock::loadCatalog()` Windows (`AppDock.cpp:840-863`), saat insert `.lnk`:

```
keywords = parent folder names (Start Menu tree, e.g. "Microsoft Visual Studio 2022")
         + " " + completeBaseName (sudah jadi name; exe basename kalau beda)
         + optional: IShellLinkW::GetDescription / GetArguments path tokens
```

Implementasi minimal (tanpa COM .lnk dulu):
- Ambil 1–2 parent folder dari path `.lnk` relatif terhadap Start Menu root → sisipkan ke `app.keywords`
- Tambah `QFileInfo(target).completeBaseName()` kalau beda dari display name (bantu “chrome” → Chrome)

COM `IShellLinkW::GetDescription` boleh ditambahkan **opsional** di file yang sama jika murah; tidak wajib untuk v1.

### 2. UWP / Store apps via `shell:AppsFolder`

File baru (atau blok `#ifdef Q_OS_WIN` di AppDock): enumerasi AppsFolder + launch AUMID.

**Enumerasi** (sekali saat `loadCatalog()`, lazy):
1. `SHParseDisplayName(L"shell:AppsFolder", nullptr, &pidl, 0, nullptr)`
2. Bind `IShellItem` → `IShellItemFolder` → `IShellItemArray` / enum objects
3. Per item: `GetDisplayName(SIGDN_NORMALDISPLAY)` + `GetDisplayName(SIGDN_DESKTOPABSOLUTEPARSING)` (AUMID / path)
4. Skip framework/pakai filter: hanya item launchable; skip name kosong; skip duplikat dengan catalog exe yang sudah ada (match by display name case-insensitive)
5. Insert `DockApp`:
   - `id` = AUMID (parsing name), e.g. `Microsoft.WindowsCalculator_8wekyb3d8bbwe!App`
   - `name` = display name
   - `command` = **empty** (bukan exe)
   - `key` = AUMID lower
   - `keywords` = display name + package family name (split `_` / `.` tokens)
   - `categories` = kosong → group “Other” (atau heuristic: Calculator→Utilities nanti)

**Launch** (`AppDock::launchNew` + path yang dipakai launcher):
- Jika `id` mengandung `!` (AUMID) atau `command` kosong dan id terlihat seperti AUMID:
  - `CoCreateInstance(CLSID_ApplicationActivationManager)` → `IApplicationActivationManager::ActivateApplication(aumid, nullptr, AO_NONE, &pid)`
- Fallback lama: `QProcess::startDetached` untuk exe

Cek juga `activate()` / `openIfFolder` — launcher search pakai jalur yang sama dengan dock launch.

### 3. Multi-token content-based scoring

`LauncherModel.h` — pure, unit-testable.

**Target behavior:**
- Query 1 kata → skor seperti sekarang (kompatibel)
- Query multi-kata `"visual studio"` → token `visual` + `studio`
- **AND semantics**: semua token harus match (score > 0) di **name + keywords** (gabung string: `name + " " + keywords`)
- Skor akhir = **rata-rata** skor per-token, **+15 bonus** kalau semua token match di *name* saja (bukan cuma keywords)
- Pertahankan ranking by score → uses → A–Z

**API:**
```cpp
inline int scoreToken(const QString &token, const QString &name, const QString &keywords);
inline int score(const QString &query, const QString &name, const QString &keywords); // multi-token di sini
```

`score()` lama dipecah: loop token, AND, average + name bonus.

**Contoh:**
| Query | Name | Keywords | Hasil |
|-------|------|----------|-------|
| `visual studio` | Visual Studio 2022 | Microsoft … | match (studio di name, visual di keywords/folder) |
| `calc` | Calculator | … | prefix |
| `zzz calc` | Calculator | … | 0 (AND) |

### 4. launcherApps — tidak banyak berubah

`AppDock::launcherApps()` (`AppDock.cpp:351-359`) sudah kirim `keywords` + `category`. Cukup pastikan UWP entries ikut `m_catalog` dan punya `keywords` terisi.

`installedApps()` (dock picker) — boleh filter juga pakai keywords opsional; **di luar scope wajib** kecuali murah.

## Implementation order

1. **LauncherModel multi-token** + unit tests (pure, cepat di-verify di Linux)
2. **Keywords dari Start Menu path** di `loadCatalog` (Windows `#ifdef`)
3. **UWP enumerasi** `shell:AppsFolder` → catalog
4. **UWP launch** `IApplicationActivationManager`
5. Docs + release notes
6. Build Linux (`notch_core` / `tst_core`); Windows path = CI `windows.yml`

## Risks & mitigations

| Risk | Mitigation |
|------|------------|
| AppsFolder COM gagal / lambat | Lazy saat first `loadCatalog`; try/catch HRESULT; skip on failure (tetap Start Menu) |
| Duplikat UWP vs .lnk | Skip UWP jika display name sudah ada di catalog |
| AUMID launch butuh COM apartment | Init di GUI thread (`COINIT_APARTMENTTHREADED`) seperti `WinVolume.cpp:15` |
| Multi-token terlalu ketat | AND hanya; tanpa fuzzy di v1. Subsequence lama tetap per-token |
| Ketergantungan shell32 | Pastikan CMake Windows link shell32/ole32 (biasanya sudah via Qt) |

## Verification

**Linux ( lokal ):**
```bash
cmake --build build --target notch_core tst_core
ctest --test-dir build -R tst_core --output-on-failure
```
- Test multi-token: `"fire fox"` → Firefox; `"zzz fire"` → 0
- Single-token regression test yang sudah ada tetap hijau (`tst_core.cpp:1671-1674`)

**Windows (user / CI):**
1. Shift+Space → ketik app Store (mis. “Calculator”, “Photos”) → harus muncul
2. Ketik multi-kata “visual studio” / “windows terminal” → ranking masuk akal
3. Enter → app terbuka (UWP via ActivateApplication)
4. App klasik tetap jalan (Chrome, VS Code, …)
5. Start Menu apps yang dulu ada tetap ada (tidak hilang)

**Debug (opsional):** log `qCInfo` jumlah catalog Start Menu vs UWP saat `loadCatalog()` selesai.

## Out of scope (v1)

- Typo tolerance / fuzzy berat
- Search recent files / web
- Category chips khusus Windows
- Icon UWP (boleh placeholder executable icon)
- Super-key launcher di Windows
